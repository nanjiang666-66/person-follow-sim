### 3.1 同轮识别时间日志

用户补充日志覆盖ROS时间1791377031.248–1791377086.278；CSV覆盖1791377034.121–1791377086.872。按CSV的ros_s减wall_s估算起点为1791377034.07095，日志各窗口结束点对应录制约-2.82、2.21、7.19、12.22、17.22、22.21、27.22、32.19、37.22、42.20、47.18、52.21秒。日志与本轮匹配，timing_debug已在Ubuntu实际生效。

开头两组窗口跨越CSV起点，其统计包含录制开始前的帧。仅对结束点在录制5秒之后、结束之前的10组窗口按样本数加权，得到：

| 项目 | 近似加权平均 / 最大 | 含义 |
|---|---|---|
| color_rx | 182 / 480 ms，751个样本 | 识别进程执行彩色订阅回调时，原图像已具有这些时间年龄 |
| depth_rx | 183 / 480 ms，762个样本 | 深度订阅回调对应年龄 |
| color_entry | 185 / 480 ms，722个样本 | 同步后完整处理开始时的彩色图年龄 |
| depth_entry | 184 / 480 ms，722个样本 | 同步后完整处理开始时的深度图年龄 |
| compute_to_pub | 57 / 173 ms，634个样本 | 处理开始至准备发布可信XYZ的耗时，未含显示尾段和publish调用内部 |
| xyz_pub | 238 / 580 ms，634个样本 | 即将发布可信XYZ时的原始彩色图年龄 |
| pair_gap | 19 / 67 ms，722个样本 | 彩色与对齐深度的时间戳差，不是同步等待耗时 |

日志逐窗口均值已取整，加权结果为近似值；不同项样本数不同，不能直接相减得出精确阶段耗时。全帧均有XYZ的7.19–37.22秒窗口中，color_entry均值144–217 ms，compute_to_pub均值51–73 ms，xyz_pub均值195–290 ms。例如7.19秒窗口三项均为64个样本，对应198+66≈264 ms，说明进入识别前的年龄贡献大于当前帧处理时间。

当前代码在同一ROS执行线程的同步回调中完成模型、深度处理和显示；回调墙上占用比例在上述窗口约87–96%，具备积压的条件。这不是CPU利用率。color_rx和color_entry都已明显偏旧，优先调查识别入口前的传输、订阅队列和执行器等待；入口诊断仍包含相机采集/驱动、USB/虚拟机及ROS排队，不能仅凭这些数据把原因完全归于某一项。

32.19秒结束的窗口报告xyz_pub最大580 ms，CSV约29.40秒的新接收估算为580.266 ms，两者吻合，超过控制0.5秒门限。完整日志中673 ms的最大值位于跨越CSV起点的窗口，与启动约0.15秒收到的673.095 ms相符，不能当作正常测试后段的新峰值。控制按原时间年龄停止有证据，优化方向为降低处理入口前的旧帧积压，再比较发布年龄和指令连续性；目前不改变0.5秒门限。

42.20秒与47.18秒结束的两个窗口仍处理77和70对图像，processed约15.5和14.1 FPS；可信XYZ仅21和41次。这与38–44秒测距拒绝相符，未显示视觉节点整段停止处理图像。此处应结合实际遮挡/动作分析人体掩码及深度支持，不能把测距中断与29秒的数据过期混为同一个原因。
