# 正常退出前归零测试

目的：在小车运动时，让监督节点收到与Ctrl+C相同的SIGINT正常退出，保留Gazebo、目标和CSV记录节点，核对退出前的最终零指令和实际停车。

本轮使用away运动，但CSV前缀是normal_exit，不覆盖已通过的正常away记录。新增的是共享目录中的Shell脚本，可以直接执行，无需重新编译ROS包。

## 操作

1. 结束上一套仿真，在Ubuntu终端A启动：

   ```bash
   bash /mnt/hgfs/ubuntu-workspace/person_follow_sim/scripts/run.sh normal_exit
   ```

2. 观察小车开始跟随；建议在目标持续远离阶段、仿真约10–30秒执行下一步。必须在小车有非零前进指令时测试，已经停稳时退出不能证明运动中归零。

3. 在另一个Ubuntu终端B执行：

   ```bash
   bash /mnt/hgfs/ubuntu-workspace/person_follow_sim/scripts/request_normal_exit.sh
   ```

   脚本将安装路径解析为实际可执行文件，再查找同一文件对应的唯一进程；若不是唯一进程就停止。发送SIGINT并等待进程退出，最多5秒，不发送强制终止信号。看到 `Supervisor exited` 只说明进程已结束，停车结果仍需CSV和动作验证。

4. 保持Gazebo不暂停，让小车和记录继续运行至少5个现实秒，观察是否停稳。然后在终端A按Ctrl+C结束整套仿真，在B收集记录：

   ```bash
   bash /mnt/hgfs/ubuntu-workspace/person_follow_sim/scripts/collect_records.sh
   ```

5. 回传脚本完整输出、是否观察到小车停车，以及 `Copied: normal_exit_...csv` 文件名。宿主机再读取共享目录中的该文件。

## 记录判定

- 退出前确实有运动和新鲜odom，且只有监督节点发布最终/cmd_vel。
- 记录中最后一条接收到的速度命令为零；退出后cmd_age持续增长，证明记录节点仍工作而最终命令发布停止。
- /clock和新鲜odom继续推进，实际线速度和角速度下降到近静止并保持，不用旧odom判断停车。
- 若出现退出后再次非零命令、持续运动或Gazebo同时退出，则不能判通过，需要检查完整记录。

监督节点当前停止路径发送零Twist，不更新/follow/state；退出后CSV可能保留旧的following状态，判断依据命令接收年龄、新鲜odom和运动。CSV约50ms采样，不能保证逐条捕获5次归零发布或测出精确的信号到停车延迟。

本文件不能按常规away运行check_recording.py：监督节点主动结束后，命令年龄增大是本项测试的预期；常规检查器的持续命令新鲜度要求适用于节点应持续运行的场景。本项读取独立normal_exit记录判定，正常away的PASS不受影响。

本测试验证SIGINT正常退出的停止路径，不验证强制终止、程序崩溃或硬件掉电。实车的底盘指令超时保护仍在后续阶段实现。
